### 关键决策（后续必须知道）

1. **SharePackage 保留了 granularity 与 ChainAnchor**。需求草稿把它们砍成"只有加密档 + anchor:{type:'local'}"，
   但那样会删掉 E1 的三档粒度演示，并让 provenance/chainStore（禁改）的类型对不上。改成：
   `photos: EncryptedPhoto[]`（加密档逐张密文）+ `plainPhotos?: string[]`（明文档），版本升到 ts-2026.2。
2. **Memory.photos / coverIndex 在类型上是可选的**。因为 src/experiments/fixtures.ts（禁改）构造 Memory 时不带
   这两个字段；设为必填会让 `tsc --noEmit` 直接红。运行时统一走 store/memories.ts 的
   `photosOf / coverOf / safeCoverIndex` 归一化，旧 thumbBlob 记录会被当成单图迁移。thumbBlob/thumbMime 保留为 deprecated 可选。
3. **pack 的输入是 `photos: Uint8Array[]`，不是 `File[]`**。File 是 DOM 类型，进 share 层会让 Node 里的 vitest 跑不了；
   压缩放在 Tab2，share 层只收字节。
4. **compressImage 改为返回 `Uint8Array`**（按需求签名）；原"带尺寸"的能力保留为 `compressImageWithMeta`。
5. **unpack 对旧版本抛 `OldShareVersionError`**（需求要求"解析抛错"）；其他畸形输入仍返回结构错误、不抛。
6. **承诺完全没动**：仍是 SHA256(tag‖salt‖intensity)。新增测试用"解密后重算承诺"来锁死这一点。
7. **coverIndex 进签名**，改封面会让验签失败。
8. css 未改，星星/缩略图/轮播全部用内联样式。

### 顺手修的 bug

`unpack.validateMeta` 原来用共享的 `errors` 数组判断"本次校验是否通过"，
验签失败时 errors 非空 → meta 永远被判缺失。改成局部数组判断。

  Tab1 显示"3 张"、旧版本报"版本过旧"。
- 构建：vite build 通过，70KB JS。

## MD-2：LLM 分层（查询解析 + 润色 + self_check）

新增：`src/agent/llm_client.ts`（OpenAI 兼容，10s 超时 / 重试 1 次 / 连败 2 次熔断 60s）、
`query_parse_llm.ts`（问题→{tag,timeRange,keywords}，失败退回 extractTag）、
`llm_paraphrase.ts`（只改表达，prompt 四条硬约束）、
`self_check.ts`（纯函数：多引/漏引/编造/空输出/JSON 输出全拦）。
`tests/self_check.test.ts` 14 个用例；`.env.example`；dotenv 进 devDependencies。

### 关键决策

1. **explain() 保持同步**，另开 `explainWithLLM()`。理由：counterfactual 测试与反事实检验都同步调用它，
   改成 async 会破坏既有测试与"决策纯函数"边界。UI 只把 tabLibrary 的一个调用点改成 await
   （该文件不在 MD-2 白名单，属必要例外，已在 README 差异清单第 13 条说明）。
2. **self_check 统一 ID 口径**：回答里是 shareId（s_xxx），citedEdgeIds 是边 ID（e_xxx），
   两边都折算成 shareId 再比。否则"同一来源两种写法"会误判。
3. **looksLikeStructured 不能把 `[gift:...]` 开头的正常回答当数组**——这个坑被单测抓到并修正。
4. **dotenv 放 devDependencies**：VITE_ 变量由 Vite 注入，dotenv 不是运行时依赖。

- mock LLM 端到端 11/11：合规润色生效（"接受了"→"收下了"）；mock 塞假 ID 时被 self_check 拦住，
  连续两次失败后降级规则版 + UI"规则版回答"角标；引用条目数两次都是 1；反事实检验照常。
