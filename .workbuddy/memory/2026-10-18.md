## TrailShare / 旅迹信物 — 从零实现（Vite + Vanilla TS，零后端）

按用户提供的详细技术方案生成完整仓库 `F:/project/trailshare`。

- 分层：`crypto/`（Ed25519 WebCrypto 优先 + noble 兜底、AES-GCM+PBKDF2、承诺、L0 哈希链）、
  `share/`（pack 七步 / unpack 五步）、`store/`（idb，统一存 ArrayBuffer）、
  `agent/`（fuse 三策略、recommend、explain、counterfactual、multihop，全部纯函数）、`ui/`（三 Tab）。
- 测试：92 个 vitest 用例全绿；`vite build` 通过（约 60KB JS）。
- 实验：E1 隐私 0/0.833/0.983；E2 忠实度 0.833；E3 主场景 1/6、贴身场景 4/6；E4 三跳后仅剩 15.8%。
- 端到端用无头 Edge + CDP 脚本验证 22 项（含双浏览器上下文互发、错误口令、链关闭仍可接受）。

### 关键决策（后续改动需知）

1. **反事实用 `rankTags()` 而非方案的 `recommend(tag)`**：后者会把被解释标签当目的地排除，
   导致该标签分数永不参与比较，指标失真。这是对方案的有意修正。
2. **`plain` 档新增 `payload.plainPhoto / plainMeta`**：方案 schema 没给明文留位置。
3. **链校验三态**（true/false/null）：跨设备看不到对方链，`prevHash` 命中本地账本多数不成立。
4. **E1 隐私分是自定义加权模型**（0.4/0.3/0.3），权重在 `e1_privacy.ts` 常量里。
5. **E4 用对数归因**算直接/间接份额，保证随跳数单调。
6. **`commitment_only` 不可接受进记忆库**（永远没有语义），UI 需明示。
7. 发件人昵称可填但**不参与验证**，身份永远以公钥为准。
8. 应用代码 2433 行（不含 experiments/tests），CSS 201 行。

### 环境注意

- 必须用 http(s) 打开；`file://` 下 IndexedDB/WebCrypto 不可用，应用会显示"启动失败"。
- 本机 Chrome 无、Edge 有；无头调试用 `msedge --headless=new --remote-debugging-port`。
- `curl localhost` 会走代理返回 502，需 `--noproxy '*'` 且用 `127.0.0.1`。
